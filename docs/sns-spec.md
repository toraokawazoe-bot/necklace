受注管理アプリ(necklace-48ca)の「SNS運用」タブを作り直す。使うのは しおん(iPhone)と とらお。

## 0. 決まったこと(要件定義の答え)

| 問い | 決定 |
|---|---|
| 目的 | 毎日の投稿の管理 / アイデア整理 / 毎週の振り返り / 投稿の中身を作る手伝い の4つすべて。中に詰めたナレッジで支える |
| アイデアの入れ方 | 1行メモ+参考URL+スクショ(アプリ内)。さらに iPhone の共有ボタンから送れる(iOSショートカット経由) |

## 1. 画面ごとの要件

### 今日(最初に開く画面)
- 今日やること:ストーリーズ ○/2枚、今日の予定投稿(週の方針から)、「数字を入れて」(投稿から3日たって再生数・保存数が未入力のもの)、アイデア箱の未仕分け件数。
- 今週の進み具合:TikTok ○/3、Instagram ○/2(リール ○/1)、ストーリーズ ○/14、「人が着けた姿」の割合、告知投稿の本数(1本超えたら注意)。
- 季節のお知らせ:下のカレンダーで「投稿開始の目安」に入ったイベントを出す。
- 今週の注文数とチャネル別(既存の order.channel を使う)。

### アイデア箱
- 1行メモ、参考URL、スクショ(既存の画像アップロードの仕組みを流用)を入れる。入力は5秒で終わる形。
- iOSショートカットから届いたものもここに入る(下の「共有ボタン」)。
- 状態:未仕分け → 採用 → 投稿済み / 却下。タグ:型(下の型カード)、季節、手間(S/M/L)。
- 週1回の仕分け:影響(1〜5)×手軽さ(1〜5)で点数。16点以上は採用の候補、9点以下は却下の候補として色分け。30件を超えたら古いものを却下候補に。
- 採用したアイデアから「作る」に進める。

### 作る
- 型を選ぶ(下の型カード。分析で伸びた型を上に、確度の表示つき)。
- 選ぶと:1枚目の文字の候補(フック集から型と目的に合うもの)、写真/動画の並べ方、文章テンプレート(色・素材・長さ・一言・キーワードを埋める)、キーワード候補、ハッシュタグ候補(大1+中2+小1+自社1)。
- Instagramはハッシュタグ5個を超えたら警告。投稿前チェック10項目。
- 「投稿した」で記録:場所(TikTok写真/TikTok動画/Instagramフィード/リール/ストーリーズ)、型、使ったフック、キーワード、元のアイデア(あれば投稿済みにする)、投稿日時。
- 第2段階のAIボタン用の場所だけ用意してもよい(今回は無効表示「準備中」)。

### 振り返り
- 投稿ごとの一覧:日付、場所、型、再生数、保存数、保存率。3日たって未入力のものは目立たせる。
- 型ごとの比べ:本数、再生の中央値、保存率の中央値、判定。判定ルール:
  - 3本未満 → 「保留(まだ判断しない)」
  - 直近3本のうち2本以上が、全投稿の再生中央値を上回る → 「続ける」
  - 直近3本がすべて下位25% → 「やめる候補」
  - それ以外 → 「直す(1枚目・文字・時間のどれか1つだけ変える)」
- 週の合計(自動):本数、再生、保存、保存率。目標の本数との比較。同じ週の注文数(チャネル別)。
- 週の方針(設定):本数、時間、休みの曜日、型の割合、キーワード一覧。
- 週のふり返りメモ:続けること/困ったこと/来週1つだけ試すこと(KPT)。

## 2. 共有ボタン(iPhone)
- API:`POST /api/ideas`(サーバー側。Firebase Admin SDKで書く)。本文 `{ token, text?, url? }`。token は環境変数 `IDEAS_TOKEN` と一致したときだけ受け付ける。text/url の長さ上限を設ける。
- 「アイデア箱」の中に「共有ボタンの設定」画面:iOSショートカットの作り方を手順で表示し、トークンとURLをコピーできるようにする。
  手順の例:ショートカット → 新規 → 「共有シートに表示」をオン、受け取る種類=URLとテキスト → 「URLの内容を取得」アクション、URL=https://necklace-48ca.vercel.app/api/ideas、方法=POST、本文=JSON(token, url=ショートカットの入力, text=「入力を要求」で一言)→ 名前「740にメモ」。
- とらおも同じショートカットを入れれば2人とも送れる。

### 3-1. 740NLLの分析の結論(2026-10-13、自分のアカウント+同じビーズ系11アカウント)
TikTok 伸びる:
1. 1枚目に「人が身に着けている姿」(服やおでかけの写真、または顔を切った首元の着用)。1枚目が物だけは伸びない。確度:中

6. 値段を1行目に(例「これ1000円台で買えます」5.2万回)。確度:低

### 3-6. ハッシュタグとキーワード

## 4. AI(Gemini)の決まり(2026-10-13 追加。第2段階用。無料枠のみ)

AIに「投稿写真の並び順・1枚目の文字・文章」を提案させる。AIは提案役。決めるのは人。
前提:**ログイン必須モードを先に有効にする**(今は誰でも開ける。直すまでAIは入れない)。
考え方(メタ思考):先に「どの型か・なぜか・誰に向けるか」を考え、そのあとで書く。順番を逆にしない。

### 4-0. 無料枠の事実確認(2026-10-13 に公式ページで確認)
- 無料枠で使える画像入力対応モデルがある(Flash系・Flash-Lite系が画像入力に対応と記載)。出典:https://ai.google.dev/gemini-api/docs/pricing
- 無料枠は「Content used to improve our products = Yes」。有料枠は No。出典:同上
- 無料(unpaid)サービスでは、送った内容と出力がGoogle製品の改善に使われる。人間の担当者が入出力を読むことがある(アカウント・キー・プロジェクトとは切り離した状態)。「機微・秘密・個人情報を送るな」と明記。出典:https://ai.google.dev/gemini-api/terms
- 制限は3種類(RPM=毎分リクエスト、TPM=毎分トークン、RPD=毎日リクエスト)。**キー単位ではなくプロジェクト単位**。どれか1つ超えるとエラー。出典:https://ai.google.dev/gemini-api/docs/rate-limits
- **未確認**:無料枠Flashの具体的な数値(RPM/RPD)。公式ページ本文に数値が出ず、AI Studioの画面でだけ見られる。→ とらおがAI Studioで確認して下の「アプリ側の上限」の根拠欄に書き込む。確認前は下の保守的な値を使う。
- **未確認**:モデル名は頻繁に変わる。コードにモデル名を直書きせず、環境変数 `GEMINI_MODEL` で差し替え可能にする。使うのは「無料枠に載っているFlash系で画像入力できるもの」だけ。

### 4-A. 判断の決まり(AIが従うルール。根拠は§3のみ。§3に無いことは言わない)
各項目は「§番号」を持つ。AIは選択ごとに従ったルールの§番号を出力に書く。
1. **1枚目**(§3-1①・§3-8・§3-9):人が身に着けた姿の写真があれば必ず1枚目にし、一言の文字を乗せる案にする。無ければ「着用写真がありません。撮ってから投稿を」と言い、**物だけの1枚目を代わりに推さない**。撮影案(服+ネックレスの自撮り/顔を切った首元)を出す。
2. **並べ方**(§3-9):1 着用+一言 → 2〜3 別角度・横顔 → 4 ビーズの質感 → 5 色展開・置き撮り → 6 長さが分かる写真 → 最後 値段・買い方・次の予告。5〜8枚。足りない役割は `missing_shots` に出す。色味が揃わない写真は注意に出す。
3. **型の選び方**(§3-2):型カードの中から選ぶ。カードに無い型を作らない。「推論」の型は確度を「推論」と出す。作っている過程の型はTikTok/フィードに推さない(§3-1・§3-2注意)。
4. **1枚目の文字**(§3-3):フック集の型に沿った3案。そのまま引用か、数語の差し替えまで。値段・長さ・地名は入力値のみ。
5. **文章**(§3-4・§3-6):1行目か最初の20字に検索語を1つ入れる。優先は「ビーズネックレス」。同じ語を詰め込まない(文章・画面の文字・タグで合計3か所まで)。TikTok用とInstagram用を分けて出す。
6. **ハッシュタグ**(§3-6):Instagramは**5個まで**(大1・中2・小1・自社#740NLL)。TikTokは文章テンプレートの範囲。6個以上を出さない。
7. **事実を作らない**:値段・長さ・素材・色・在庫・日時は**ユーザーが入力した値だけ**使う。入力が無い項目は `【要入力】` と出し、推測で埋めない。写真から長さや素材を断定しない。
8. **言ってはいけない**(§3-12):「金属アレルギー対応」「絶対似合う」など断定の診断・効能。他ブランドを誤認させる書き方。著作権音源の指示。同じ文章の使い回し。
9. **告知の本数**(§3-0・§3-11):告知・販売だけの投稿は週1本まで。今週すでに1本ある場合、告知型を選んだら警告する(今週の告知数はアプリが数えて渡す)。
10. **文体**:平易な日本語。です・ます調かやわらかい口語。誇張・煽りなし。絵文字は多用しない。
11. **投稿前チェック**(§3-8):10項目を1つずつ「OK/NG/不明」で返す。写真から判断できない項目(代替テキスト・投稿時間など)は「不明(人が確認)」。
12. **確度**:各提案に確度(高/中/低/推論)を付ける。根拠は§3-1・§3-2の確度表示をそのまま使い、勝手に上げない。
13. **理由**:スライドごとに「なぜこの順番か」を1文で。必ず従った§番号を添える。

### 4-B. 出力の形(固定JSON。アプリが検証する)
Geminiのstructured output(JSONスキーマ指定)で受け取る。自由文は禁止。
```
{
  "format_id": "型カードのID(アプリが持つ一覧のどれか)",
  "format_reason": "なぜこの型か・誰に向けるか(メタ思考。2文以内)",
  "slide_order": [ { "image_index": 数字(0始まり、送った順), "role": "着用|別角度|質感|色展開|長さ|値段・買い方|その他", "reason": "なぜここか(1文)", "rule": "§3-9 など" } ],
  "missing_shots": [ "足りない写真と撮り方" ],
  "hook_candidates": [ { "text": "1枚目の文字", "rule": "§3-3 のどの型か" } ],   // 3件ちょうど
  "caption": { "tiktok": "...", "instagram": "..." },
  "keyword": "検索語1つ(優先: ビーズネックレス)",
  "hashtags": { "instagram": ["#..."],  "tiktok": ["#..."] },   // instagram は5個以下
  "checklist": [ { "item": "§3-8の項目名", "result": "OK|NG|不明", "note": "" } ],   // 10件
  "warnings": [ "注意" ],
  "confidence": "高|中|低|推論"
}
```
アプリ側の検証(通らなければ採用しない):
- JSONとして読める/必須項目がある/`hook_candidates`が3件/`checklist`が10件。
- `image_index` が送った枚数の範囲内で、重複なし。
- `hashtags.instagram` が5個以下。`keyword` が `caption` の最初の行に含まれる。
- `caption` に入力していない数字(円・cm)が出ていない。禁止語(アレルギー対応・絶対 など)を含まない。
- 不正なら**1回だけ**「JSONの形を直して」と再依頼。それでも不正ならエラー表示して終了(自動で繰り返さない)。

### 4-C. 使い方の制限
- 呼び出せるのはログイン済みの運営者(しおん・とらお)だけ。未ログインは401。
- 回数:1人1日20回まで、1分に3回まで(アプリ側。無料枠の上限より低く設定。無料枠の数値は4-0の通り未確認なので、確認後に必要なら下げる)。超えたら「今日はここまで。明日また使えます」と表示。
- 画像:1回8枚まで。送る前にブラウザ側で長辺1024px以下のJPEGに縮小。1枚あたり約1MB以下。動画は送らない。
- 通信:サーバー側のAPIルートから呼ぶ。タイムアウト30秒。失敗時は「うまく作れませんでした。もう一度押してください」。**自動再試行ループはしない**(押すのは人)。
- 課金ガード:APIが課金・上限エラー(429、RESOURCE_EXHAUSTED、billing関連)を返したら、そこで止めてメッセージを出し、その日はボタンを無効にする。**有料モデルや別キーへ自動で切り替えない**。Google側でも請求先アカウントを紐づけない(無料枠のまま)。
- ボタンの二度押し防止(処理中は無効)。

### 4-D. プライバシー
- 送るのは「選んだ投稿用写真」と「商品欄に打った項目(色・素材・長さ・値段・一言)」だけ。
- **注文・お客さんの情報(名前・住所・連絡先・注文内容)は絶対に送らない**。受注データはAIのコードから読めない作りにする。
- 無料枠の内容はGoogleの製品改善に使われ、人間が読むことがある(4-0の出典)。そのため、他人の顔が写った写真・お客さんの写真・個人が特定できる情報は送らない。ボタンの近くに常時表示:「他の人の顔が写っている写真、お客さんの写真は入れないでください(無料のAIは内容が改善に使われます)」。
- 送信前の確認チェック1つ:「この写真に、許可のない人は写っていません」にチェックしないと送れない。
- 写真はAI呼び出しのために保存し直さない(送信後に破棄。既存のアップロード保存とは別)。

### 4-E. 人が決める範囲
- AIの出力は**提案**。並べ替え・文章の書き換えは自由。自動投稿は一切しない。
- 提案を採用したら記録する:`ai_used`(true/false)、`ai_format_id`、`final_format_id`(最終的に選んだ型)、採用したフックが「AI案/テンプレ/自分」のどれか。
- 振り返りで「AI案を使った投稿」と「自分で作った投稿」の再生数・保存率を比べられるようにする(§1の判定ルールは変えない。比べる欄を足すだけ)。
- AIの提案は§3と矛盾してはならない。矛盾に気づいたら人が`warnings`を見て直す。

### 4-F. 鍵の扱い
- `GEMINI_API_KEY` は**とらおがGoogle AI Studioで作る**。保存先は**Vercelの環境変数だけ**(サーバー側のみ)。
- `NEXT_PUBLIC_` を付けない。画面・ブラウザ・Firestore・ログ・Gitに出さない。`.env`ファイルはコミットしない。
- 画面に出すのは「AI利用可/不可」だけ。キーがなければボタンを「準備中」にする。
- 漏れた疑いがあれば、AI Studioでキーを削除して作り直し、Vercelの値を差し替える。

### 4-G. 受け入れ確認(これが全部通ってから公開する)
1. **ログイン必須**:ログアウト状態で `/api/ai/...` を呼ぶと401。画面も開けない。
2. **鍵が出ない**:ブラウザのソース・通信タブ・ビルド成果物に `GEMINI_API_KEY` の値が無い。
3. **着用写真あり**:着用写真を含む4枚を送ると、`slide_order[0]` が着用写真で、理由に§3-9が付く。
4. **着用写真なし**:商品だけ4枚を送ると、1枚目を商品にせず「着用写真を撮ろう」と`missing_shots`と`warnings`に出る。
5. **ハッシュタグ**:Instagram用が必ず5個以下。6個にされたら検証で弾かれる。
6. **事実を作らない**:値段・長さを未入力で依頼すると `【要入力】` になり、数字が出ない。
7. **禁止語**:出力に「アレルギー対応」「絶対似合う」が出ない(出たら弾く)。
8. **回数制限**:21回目は拒否され、分かりやすい文言が出る。1分に4回目も拒否。
9. **失敗時**:キーを一時的に不正にすると、エラーメッセージが出て、自動で何度も呼ばれない。課金系エラーを模擬すると、その日のボタンが無効になる。
10. **個人情報**:送信内容(サーバーのログで確認)に注文・お客さんの項目が含まれない。確認チェックを入れないと送れない。
11. **記録**:採用して投稿を記録すると `ai_used` と型IDが残り、振り返りで比べられる。
12. **形式**:壊れたJSONを返させた場合、1回だけ直し依頼し、だめなら終了する。
